# Tasks — slice 1: Local ledger and read path

Each `D<n>` is a decision in [design.md](design.md), which carries what to build, including the
column tables ([Data model](design.md#data-model)), the response bodies, layouts and messages
([Surfaces](design.md#surfaces)) and the walk plan ([Walkthrough plan](design.md#walkthrough-plan)).
The pre-proposal
([2026-10-17-slice-1-local-ledger-and-read-path.md](../../../.ai/pre-proposals/2026-10-17-slice-1-local-ledger-and-read-path.md),
*PP*) keeps the authority trail; nothing here needs it to build. Load `pp-workflow`, `pp-general`, and the path skill of every package a group
touches (`pp-backend`, `pp-database`, `pp-testing`, `pp-cli`) before code.

Every group ends with `pnpm check` exiting 0, then a commit staged by path and pushed
(`git push -u origin HEAD` the first time; [root AGENTS.md → Commit and push as you go](../../../AGENTS.md#commit-and-push-as-you-go)).
A group that adds or edits an integration test also runs `pnpm test:int` (Docker running); one that
touches an e2e test also runs `pnpm test:e2e`. Each group lands the doc updates and `Ships` ticks
its own evidence triggers; a doc task's check is that every link it adds resolves
(`node scripts/check-links.mjs <file>`). The card is `.ai/build-checklist.md` → 1 — Local ledger
and read path: its `Status` goes `[~]` with the first ticked box and `[x]` only after the walk
(Workflow follow-up).

**Ask-first:** only the rows in [proposal.md → Ask-first items](proposal.md#impact) are approved.
Anything else (another package or version, a stage, a `ci.yml` edit, an env var, an error code)
stops uncommitted for the owner. The live Resend writes in group 11 are approved one at a time,
when each runs.
