# Tasks — slice 4: Recovery

Each `D<n>` is a decision in [design.md](design.md), which carries what to build: the module layout
([Module layout](design.md#module-layout)), every wire shape, layout, message and variable
([Surfaces](design.md#surfaces)), the evidence per claim ([Evidence map](design.md#evidence-map)) and
the walk plan ([Walkthrough plan](design.md#walkthrough-plan)). The pre-proposal
([2026-10-19-slice-4-recovery.md](../../../.ai/pre-proposals/2026-10-19-slice-4-recovery.md), *PP*)
keeps the authority trail; nothing here needs it to build. Load `pp-workflow`, `pp-general` and the
path skill of every project a group touches (`pp-backend`, `pp-database`, `pp-testing`, `pp-cli`,
`pp-infra`) before code.

Every group ends with `pnpm check` exiting 0, then a commit staged by path and pushed
([root AGENTS.md → Commit and push as you go](../../../AGENTS.md#commit-and-push-as-you-go)). A group
that adds or edits an integration test also runs `pnpm test:int` (Docker running); one that touches
an e2e test also runs `pnpm test:e2e`; one that touches `infra/` also runs `pnpm synth`. Each group
lands the doc updates and `Ships` ticks its own evidence triggers; a doc task's check is that every
link it adds resolves (`node scripts/check-links.mjs <file>`). Skill edits are fact updates for
mechanisms this slice owns and loosen no rule; a commit that touches a skill says so in its body. The
card is `.ai/build-checklist.md` → 4 — Recovery: `Status` goes `[~]` in group 1 and `[x]` only after
the walk (Workflow follow-up). Slice 2's card is never touched.

**Ask-first:** only the rows in [proposal.md → Impact](proposal.md#impact) are approved. Items 1–5 and
7a are approved for apply. Items 6 and 7 (every AWS run, every live Resend write) are **held**: each
action in group 12 stops for the owner's yes in the conversation before it runs. Anything else (a
dependency, a stage, a `ci.yml` edit, another variable, flag, route field, error code or AWS
resource) stops uncommitted for the owner.
