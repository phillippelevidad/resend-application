# Tasks — slice 2: Durable ingest on AWS

Each `D<n>` is a decision in [design.md](design.md), which carries what to build: the module layout
([Module layout](design.md#module-layout)), the column table ([Data model](design.md#data-model)),
every response body, layout, message and variable ([Surfaces](design.md#surfaces)), the evidence per
claim ([Evidence map](design.md#evidence-map)) and the walk plan
([Walkthrough plan](design.md#walkthrough-plan)). The pre-proposal
([2026-10-17-slice-2-durable-ingest-on-aws.md](../../../.ai/pre-proposals/2026-10-17-slice-2-durable-ingest-on-aws.md),
*PP*) keeps the authority trail; nothing here needs it to build. Load `pp-workflow`, `pp-general` and
the path skill of every project a group touches (`pp-backend`, `pp-database`, `pp-testing`, `pp-cli`,
`pp-infra`) before code.

Every group ends with `pnpm check` exiting 0, then a commit staged by path and pushed
([root AGENTS.md → Commit and push as you go](../../../AGENTS.md#commit-and-push-as-you-go)). A group
that adds or edits an integration test also runs `pnpm test:int` (Docker running); one that touches
an e2e test also runs `pnpm test:e2e`; one that touches `infra/` also runs `pnpm synth`. Each group
lands the doc updates and `Ships` ticks its own evidence triggers; a doc task's check is that every
link it adds resolves (`node scripts/check-links.mjs <file>`). The card is `.ai/build-checklist.md` →
2 — Durable ingest on AWS: its `Status` goes `[~]` in group 1 and `[x]` only after the walk (Workflow
follow-up).

**Ask-first:** only the rows in [proposal.md → Ask-first items](proposal.md#impact) are approved.
Anything else (another package or version, a stage, a `ci.yml` edit, an env var, flag, route or error
code, a frozen migration changed) stops uncommitted for the owner. Every AWS action and live Resend
write in group 13 is approved one at a time, when it runs, and is owner-run where it touches a
secret.
